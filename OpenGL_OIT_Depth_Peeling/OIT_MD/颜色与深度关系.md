**`fboPeel_` 的深度附件是“剥离用的深度历史”，颜色附件是“当前层给 Blend 用的颜色”；二者在 Peel 阶段强相关，在 Blend 阶段才分开用。**

---

## `fboPeel_` 在本项目里干什么

| 附件     | 对象                                            | 主要用途                                                     |
| -------- | ----------------------------------------------- | ------------------------------------------------------------ |
| **颜色** | `fboPeel_.color`                                | 当前 Peel 层的光照 + 透明度 → Blend 时采样叠进 `fboAccum_`   |
| **深度** | `fboPeel_.depth`（或与 `fboAccum_.depth` 乒乓） | 记录 **这一层** 每个像素的深度 → 下一层 Peel 里当 `texture_depth` 做 `discard` |

所以：

- 深度 **不只是** “模拟乒乓”的装饰；乒乓是 **实现手段**，存的是 **真实的剥离深度**。
- 颜色 **确实是** 给混合用的 **当前层缓存**，但不是整个累积缓冲（累积在 `fboAccum_.color`）。

---

## 颜色与深度有没有关系？

### Peel 阶段：**有直接关系**

同一遍 `drawSceneLayer` 里，通过深度测试的片元会同时：

- 写 `fboPeel_.color`（`FragColor`）
- 写当前绑定的深度附件（`gl_FragCoord.z`）

同一像素、同一层：**谁赢得深度测试，谁就决定这里的颜色和深度**。  
片元里 `discard` 和 `texture_depth` 比较的是 **历史层深度**；本层深度由硬件深度测试写入。

```
Peel 一层:
  discard( vs 已剥深度 texture_depth )
       ↓ 通过
  GL_LESS 竞争 → 本像素最近的一片
       ↓
  同时写 fboPeel_.color + 当前 output 深度纹理
```

### Blend 阶段：**没有用到 peel 的深度**

```cpp
modelQuad_->Draw(..., fboAccum_.fbo,
    {{"texture_diffuse", fboPeel_.color.id}}, ...);  // 只采样颜色
```

Blend 只用 `fboPeel_.color`，**不读** peel 深度。  
混合公式只动 `fboAccum_` 的 RGBA，和 peel 深度无公式上的关系。

---

## 乒乓在解决什么？

不是“模拟效果”，而是硬件限制：

> 同一深度纹理不能在同一 Pass 里既当 FBO 深度附件被写入，又被 `texture_depth` 采样。

所以用 **`fboPeel_.depth` ↔ `fboAccum_.depth` 交替**：

```
Layer 0: 读 accum 深度 → 写 peel 深度
Layer 1: 读 peel 深度  → 写 accum 深度
Layer 2: 读 accum 深度 → 写 peel 深度
...
```

`peelAndBlend` 里重绑深度附件：

```cpp
glFramebufferTexture2D(..., GL_DEPTH_ATTACHMENT, ...,
                       depthTexture(outputDepthIndex_), 0);
```

颜色始终画进 `fboPeel_.color`；**深度写在乒乓的另一侧**。

---

## 三个 FBO/缓冲角色对比

```
fboPeel_.color     → 当前层颜色（给 Blend）
fboPeel_.depth     → 参与乒乓的“剥离深度”之一
fboAccum_.color    → 多层 Front-to-Back 累积结果（给 Final）
fboAccum_.depth    → 参与乒乓的“剥离深度”之二
```

关系可以概括成：

| 阶段  | 颜色              | 深度                            |
| ----- | ----------------- | ------------------------------- |
| Peel  | 本层 RGBA         | 本层 z，供下层 `discard`        |
| Blend | peel 颜色 → accum | 只清 accum 深度，不参与混合计算 |

---

## 对你三个说法的对应

| 你的理解               | 更准确的说法                                             |
| ---------------------- | -------------------------------------------------------- |
| 深度附件只为模拟乒乓   | ❌ 乒乓是为了 **读写分离**；深度值是 **剥离算法的数据**   |
| 颜色附件为混合缓存     | ✅ 是 **当前层** 的混合输入；**累积**在 `fboAccum_.color` |
| 颜色与深度没有直接关系 | ⚠️ **Blend 时**无关；**Peel 时**同一层、同一像素强相关    |

---

## 一句话

`fboPeel_`：**颜色 = 这一层长什么样；深度 = 这一层在多深（给下一层 Peel 用）**。  
乒乓是深度在 `fboPeel_` / `fboAccum_` 之间传递的方式；**只有 Blend 这一步才只用颜色、不用 peel 深度。**
