## 各自含义

| 调用                      | 作用                                                      |
| ------------------------- | --------------------------------------------------------- |
| `glEnable(GL_DEPTH_TEST)` | 开启深度测试；片元是否写入颜色/深度，要先和深度缓冲比较   |
| `glDepthFunc(GL_LESS)`    | 只有 **当前片元深度 < 缓冲里已有深度** 才通过（更近才赢） |
| `glDepthMask(GL_TRUE)`    | 通过测试的片元会 **写入** 深度缓冲（更新本层深度纹理）    |

OpenGL 里 `gl_FragCoord.z` 越小越近；Peel 前深度常清成 `1.0`（最远），所以第一层会从「比 1.0 更近」的片元里竞争。

## 在本项目里解决什么问题

深度剥离里有两层筛选：

```
① discard（片元着色器）
   和 texture_depth 比：去掉「已经剥过的层」

② GL_LESS（硬件深度测试）
   同一 Peel Pass、同一像素：在「剩余候选」里只留最近的一片
```

没有 ② 时，同像素多个透明面可能都写进 `fboPeel_`，顺序一乱就错。  
**深度测试与片元执行顺序无关**，远的先跑、近的后跑，近的仍会赢。

## 和 `peelAndBlend` 里的配合

**Peel 阶段**（`drawSceneLayer`）：上面三行保持有效 → 用深度测试选本层最前片元，并写入 `outputDepthIndex_` 对应的深度纹理。

**Blend 阶段**（约 287–288 行）会临时改掉：

```cpp
glDepthMask(GL_FALSE);   // 不写深度
glDisable(GL_DEPTH_TEST); // 不做深度比较
```

全屏 quad 往 `fboAccum_` 叠颜色，不需要深度竞争；叠完再恢复深度测试。

## 和 `initPeelBuffers` 里 `glClearDepth(0.0f)` 的关系

帧初两个 FBO 深度清 **0.0**（`initPeelBuffers` 190 行附近），那是 **历史深度纹理** 的初始状态。

每一层 Peel 前在 `peelAndBlend` 里对 `fboPeel_` 会：

```cpp
glClearDepth(1.0f);
glClear(...);
```

本层剥离缓冲从「最远」开始，再用 `GL_LESS` 留下本层最近的片元。

## 一句话

这三行的意义：**在每一遍 Peel 绘制时，用深度测试保证每个像素只保留当前层里最近的那一片，并把深度写进纹理，供下一层 `discard` 和乒乓深度使用**；Blend 合成颜色时会关掉，避免全屏 quad 被深度挡掉。
